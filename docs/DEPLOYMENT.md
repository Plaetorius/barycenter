## How a change reaches the live site
```
ledger YAML (verified)  ->  python -m barycenter.publish  ->  site/public/data/*  ->  next build  ->  Vercel  ->  labs.mertia.xyz/barycenter
```
1. Edit or add facts in `pipeline/ledger/` (see `docs/LEDGER.md`, `docs/VERIFY.md`).
2. `cd pipeline && .venv/bin/python -m barycenter.publish` (fails on bad data; writes `site/public/data`).
3. `cd ../site && pnpm build` to check locally, then deploy:
   `vercel deploy --prod --yes` (run inside `site/`; the project is already linked in `site/.vercel`).
   The CLI uploads the local folder; **Vercel runs `next build` in its cloud**, so the build is not on your machine.
4. The labs site needs no change for data updates (it only proxies).

There is **no Git-based auto-deploy** for Barycenter today: nothing deploys unless someone runs step 3. If you create a GitHub
repo and connect it to the Vercel project (root directory `site`), every push to `main` will deploy automatically.

## Costs and limits
Static hosting only; no database, no API keys, no secrets in the site. The LLM and search work happens offline in the pipeline.
